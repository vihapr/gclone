# gclone

Крошечная утилита для групп проектов GitLab: показать список репозиториев
группы или склонировать их все разом. Один бинарник, только стандартная
библиотека Go. Заточена под self-hosted GitLab (например, `scm.host.ru`);
живая проверка против него требует PAT со scope `read_api` (см. «Подготовка»).

## Установка

Готовые бинарники лежат в [dist/](dist/) — компилировать ничего не нужно.
Скачайте под свою платформу, положите в `PATH` и сделайте исполняемым:

| Платформа | Файл |
|---|---|
| macOS (Apple Silicon) | `dist/darwin-arm64/gclone` |
| macOS (Intel) | `dist/darwin-amd64/gclone` |
| Linux x86-64 | `dist/linux-amd64/gclone` |
| Linux ARM64 | `dist/linux-arm64/gclone` |
| Windows x64 | `dist/windows-amd64/gclone.exe` |

```bash
curl -fsSL -o gclone <raw-url-бинарника>   # Raw-ссылка на файл в репозитории
chmod +x gclone && sudo mv gclone /usr/local/bin/
```

Linux-бинарники собраны с `CGO_ENABLED=0` (статическая линковка) — работают
даже на alpine/scratch.

## Подготовка к запуску

### Как устроена авторизация

У утилиты два независимых канала авторизации:

1. **Листинг проектов** (`--analyze` и первый шаг `--clone`) — GitLab REST API.
   Нужен Personal Access Token (PAT). Без него API закрыт (401/404).
2. **Само клонирование** — subprocess системного `git`. Авторизация целиком
   на стороне git: SSH-ключи, credential helper (osxkeychain, cache, store) —
   всё, что уже настроено для обычной работы с git, работает без действий.

Токен для канала 1 ищется по цепочке — **первый непустой побеждает**:

| Приоритет | Источник | Комментарий |
|---|---|---|
| 1 | флаг `--token` | разовая передача; токен остаётся в истории shell |
| 2 | env `GCLONE_TOKEN` | рекомендуемый способ (см. ниже) |
| 3 | env `GITLAB_TOKEN` | если уже используется другими тулзами |
| 4 | `git credential fill` | системный credential helper: на macOS — Keychain, на Linux — `cache`/`store`/libsecret, что настроено |

Пункт 4 означает: если вы когда-то клонировали репозитории этого GitLab по
HTTPS и git сохранил учетные данные, токен возьмётся оттуда автоматически и
передавать ничего не нужно. Если в хранилище лежит запись с пустым паролем
(бывает), gclone её проигнорирует и честно скажет, что токен не найден.

### Где взять токен

1. GitLab → аватар (правый верхний угол) → **Edit profile** → **Personal access tokens**
   (или напрямую `https://<gitlab-host>/-/user_settings/personal_access_tokens`).
2. Add new token:
   - **Scope**: достаточно `read_api` (только чтение; для этой утилиты хватит
     с запасом). Не выбирайте `api`, если не нужно больше.
   - **Expiration** — на ваш выбор, утилита токен не хранит.
3. Скопируйте токен — он показывается один раз.

### Куда положить токен

Рекомендуемый способ — переменная окружения в файле вашего shell
(`~/.zshrc` для zsh, `~/.bashrc` для bash):

```bash
export GCLONE_TOKEN="XXXXXXXXXXXXXXXXXXXX"
```

После `source ~/.zshrc` (или нового терминала) утилита подхватит его сама.

Альтернативы:

- **Разово**: `gclone --token glpat-... --analyze <url>` — удобно для
  проверки, но токен остаётся в истории команд shell.
- **Через keychain** (тогда работает пункт 4 цепочки, env не нужен):
  выполнить любой HTTPS-clone репозитория этого GitLab и ввести токен как
  пароль при запросе — osxkeychain сохранит его сам.

Проверить, что токен подхватился, проще всего запуском `--analyze`: если
видите таблицу проектов — всё ок; ошибка 403 «нет scope» — у токена нет
`read_api`/`api`.

### Требования

- Системный `git` в `PATH` (нужен и для клонирования, и для поиска токена).
- Для готовых бинарников из `dist/` — больше ничего (Go не нужен).

## Запуск

> Флаги указываются **до** URL (стандартное поведение `flag` в Go).
> Отключение булевого флага — только через `=`: `--subgroups=false`.

```bash
# Список проектов группы без клонирования
gclone --analyze https://scm.host.ru/project-group

# Клонировать все проекты группы (включая подгруппы)
gclone --clone https://scm.host.ru/project-group

# В указанный каталог, shallow, 8 параллельно, по SSH
gclone --clone --out ~/src --depth 1 -p 8 --ssh https://scm.host.ru/project-group

# Без подгрупп, только сама группа
gclone --clone --subgroups=false https://scm.host.ru/project-group
```

Каталоги назначения зеркалят структуру GitLab: проект `project-group/backend/api`
окажется в `<out>/project-group/backend/api`.

### Параметры

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--analyze` | — | вывести список проектов (PATH / BRANCH / UPDATED) |
| `--clone` | — | клонировать все проекты группы |
| `--token` | — | GitLab API токен (PAT); перекрывает всё остальное |
| `--ssh` | `false` | клонировать по `ssh_url_to_repo` вместо HTTPS |
| `--subgroups` | `true` | включать проекты подгрупп |
| `--depth` | `0` | shallow clone (0 — полный clone) |
| `-p` | `4` | число параллельных клонирований |
| `--out` | `.` | каталог назначения |

Ровно один из `--analyze` / `--clone` обязателен.

### Поведение

- **Живой прогресс**: результат каждого репозитория (`✔/↷/✖/–`) печатается
  в момент его завершения, а не в конце. Пока клоны идут, каждые 5 секунд
  печатается пульс с реальными процентами git:
  ```
  ⏳ 3/7 готово | platform/api 45% · platform/web 12% (34s)
  ```
  (проценты берутся из `git clone --progress`; у репозиториев, ещё не
  успевших прислать процент, показывается только счётчик и время).
  Пульс печатается и при перенаправлении вывода в файл/пайп.
- **Повторный запуск**: существующий **валидный** клон (`.git` с
  верифицируемым HEAD) пропускается со статусом `skipped`. Если каталог
  существует, но это не завершённый клон (например, процесс убили посреди
  клонирования) — репозиторий получит статус `failed` с подсказкой удалить
  каталог; запуск `git clone` в непустой каталог всё равно невозможен.
- **Ctrl+C**: первое нажатие — новые клоны не запускаются, запущенные
  дорабатывают до конца; второе нажатие — немедленный выход.
- **Ошибки клонирования** не останавливают остальные; в конце печатается
  сводка вида `5 cloned, 1 skipped, 2 failed`.

### Коды выхода

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | были неудачные клоны |
| `2` | ошибка использования / токен не найден / API-ошибка |
| `130` | прервано по Ctrl+C (без неудачных клонов) |

## Пересборка

Нужен Go 1.26+ (`go version`). Из корня проекта:

```bash
# Тесты (рекомендуется перед сборкой)
go test -race ./...

# Локальный бинарник под вашу платформу
go build -o gclone .
```

Кросс-компиляция во все папки `dist/<os>-<arch>/` (статическая линковка,
`CGO_ENABLED=0` — linux-бинарники заводятся даже на alpine/scratch):

```bash
for p in darwin-amd64 darwin-arm64 linux-amd64 linux-arm64 windows-amd64; do
  ext=""; case "$p" in windows-*) ext=".exe";; esac
  CGO_ENABLED=0 GOOS="${p%-*}" GOARCH="${p#*-}" \
    go build -o "dist/$p/gclone${ext}" .
done
```

Готовые бинарники лежат в `dist/` и коммитятся в репозиторий, чтобы
пользователям не приходилось компилировать вручную (см. «Установка»).
После изменения кода не забудьте пересобрать все платформы и закоммитить.
