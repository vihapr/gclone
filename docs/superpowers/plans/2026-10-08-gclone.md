# gclone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CLI `gclone` — список (`--analyze`) или параллельное клонирование (`--clone`) всех репозиториев группы GitLab, с авторизацией через существующие системные credential'ы git.

**Architecture:** Один package main, 4 файла. Токен: цепочка флаг → env → `git credential fill` (keychain). Листинг: GitLab REST API с пагинацией `X-Next-Page`. Клонирование: subprocess системного `git` в пуле воркеров — вся авторизация клонирования остаётся на стороне git.

**Tech Stack:** Go 1.26, только stdlib (`flag`, `net/http`, `os/exec`, `context`, `sync`, `signal`).

**Spec:** `docs/superpowers/specs/2026-10-08-gclone-design.md`

## Global Constraints

- Только stdlib; ноль сторонних модулей; `go.mod`: `module gclone`, `go 1.26`
- package main; файлы: `main.go`, `gitlab.go`, `creds.go`, `clone.go` + `*_test.go`
- Exit codes: `0` — успех; `1` — были неудачные клоны; `2` — usage/токен/API-ошибки; `130` — прервано по Ctrl+C без других неудач
- Пользовательские сообщения (usage, ошибки, вывод) — на русском; идентификаторы кода — английские
- Коммит после каждой задачи; сообщения в стиле `feat:`, `test:`, `docs:`

## Review Focus

Тесты на эти сценарии уже встроены в задачи:

1. URL с трейлинг-слэшем `https://gitlab.example.com/platform/` → путь группы `platform` — Task 1
2. URL без схемы `gitlab.example.com/platform` → понятная ошибка, а не «успешный» пустой хост — Task 1
3. Keychain-токен без scope `api` → API отвечает 403 → сообщение про scope, а не стектрейс — Task 3
4. Повторный запуск: каталог репозитория уже существует → skip, не ошибка — Task 4
5. Ответ API без заголовка `X-Next-Page` (одна страница) → ровно один запрос, нет вечного цикла — Task 3
6. Пустая группа (0 проектов) в `--analyze` → `0 projects`, не паника — Task 5
7. Ctrl+C во время клонирования → запущенные клоны завершаются, остальные помечаются interrupted — Task 4

### Task 4: Параллельный клонер

**Files:**
- Create: `clone.go`, `clone_test.go`

**Interfaces:**
- Consumes: `Project` из Task 3
- Produces:
  - `type gitRunner func(ctx context.Context, args ...string) error`
  - `type CloneOptions struct { Out string; UseSSH bool; Depth int; Parallel int }`
  - `type CloneResult struct { Project Project; Status string; Err error }`; Status ∈ `cloned`, `skipped`, `failed`, `interrupted`
  - `cloneAll(ctx context.Context, projects []Project, opts CloneOptions, run gitRunner) []CloneResult`
  - `newGitRunner() gitRunner` — реальный раннер: `exec.Command("git", args...)`, combined output включается в текст ошибки

- [ ] **Step 1: Failing-тест: клонирует всё, корректные аргументы git**

3 проекта, фейковый `run` записывает args, возвращает nil. Assert: все результаты `cloned`; для каждого проекта args == `["clone", url, dest]`, где `url` = `HTTPURLToRepo` (при `UseSSH:false`) и `dest = filepath.Join(out, PathWithNamespace)`; все каталоги созданы (`os.MkdirAll` до запуска git).

- [ ] **Step 2: Failing-тесты: skip существующих, depth/ssh, ошибки**

- Каталог назначения уже существует и непуст (`os.WriteFile` файл внутрь) → `skipped`, `run` не вызывался для него; пустой существующий каталог → клонируется
- `UseSSH:true` → в args `SSHURLToRepo`; `Depth:2` → args содержат `["--depth", "2"]`
- `run` возвращает ошибку для одного проекта → тот `failed` (Err != nil), остальные `cloned`

- [ ] **Step 3: Failing-тест: Ctrl+C**

`Parallel:1`, 3 проекта; фейковый `run`: при первом вызове сигналит в канал и ждёт, пока тест отменит ctx (`context.WithCancel`); после отмены — nil. Assert: 1 `cloned`, 2 `interrupted`, 0 `failed`; запущенный клон ДОЖДАЛИСЬ (run вернулся).

- [ ] **Step 4: Упасть**

Run: `go test ./...`
Expected: FAIL — `undefined: cloneAll`

- [ ] **Step 5: Реализовать `clone.go`**

Пул: `jobs := make(chan Project)`, `results := make(chan CloneResult)`; воркеры `opts.Parallel` (минимум 1) читают из `jobs`; воркер перед каждым заданием проверяет `ctx.Err()` — если отменено, результат `interrupted`, git НЕ запускается; если запущен — выполняется до конца (контекст в `run` НЕ прерывает: воркер вызывает `run(context.Background(), ...)`, а ctx cloneAll — только флаг «больше не стартуем»). Skip: `os.ReadDir(dest)` без ошибки и `len > 0`. Отправитель закрывает `jobs`, сбор результатов — по числу проектов, вернуть срез.

- [ ] **Step 6: Зелёные**

Run: `go test ./... && go vet ./...`
Expected: PASS (тесты с каналами — с `-race`: `go test -race ./...`)

- [ ] **Step 7: Commit**

`git add clone.go clone_test.go && git commit -m "feat: parallel cloner with skip/interrupt handling"`
